## コンセプト（反証可能な面白さの仮説）

> プレイヤーは有限の札を「今切るか、この先のために温存するか」で配分し、
> 切り時の判断が当たった／外れたことを実感して面白がる。

MTG × RTS × TD というジャンルの組み合わせは仮説ではなく手段。判定対象は上記の一文に限る。
この仮説が成立するための必要条件（機構で保証する）:

- 札を**全部は出せない**（デッキ20枚に対し、ラン中に配置できる回数は約15回）
- 出す／出さないの選択が**排他的**（配置クールダウン中は他の札を出せない）
- 出さなかったことに**代償がある**（手札上限に達すればドローが墓地へ直行する）

## 遊び方

1. リアルタイムで敵ウェーブが進行する（`stepTick` が 100ms ごとに1 tick 進める）
2. 手札からタワー・罠・呪文・魔力炉を選び、盤面のセルに配置する（マナを消費）
3. 燠火（業火の設置跡）は再点火でき、終盤に手札もマナも尽きても操作対象として残る
4. 砦のライフ（初期10）が0になる前に、4ウェーブの敵をすべて処理しきれば勝利
5. スペースキーまたは⏸ボタンで一時停止できる（戦術的優位は与えない。認知負荷の緩和が目的）
6. 決着後、シードとプリセット（速攻型／重厚型）を指定して同一条件・別条件で再挑戦できる

## 主要な機構

- **カード8種**: 魔力炉（マナ源）・弓兵の塔・弩砲・火砲台・篝火（攻撃せず隣接塔を強化）・
  棘罠・業火（燠火として残り再点火可能）・時泥（減速呪文）
- **敵5種とカウンター要求**: 雑兵（基礎）・俊足（テンポ）・群れ（範囲）・重装（単体高火力）・
  鴉（飛行。弩砲以外は当たらない）。「最高効率のカードには必ず効かない相手を作る」原則で、
  弓兵が最も効率が高いまま支配戦略にならないようにしている（`domain/combat/balance.test.ts` で回帰検証）
- **地形**: 高台（火力+30%）・滞留セル（敵の移動速度を落とす）
- **プリセットデッキ2種**（速攻型・重厚型）。デッキ構築 UI の代替であり、判定するのは
  「デッキ構築の面白さ」ではなく「ラン中の札の配分」

## 判定の観点（§11）

同一プリセットデッキで3ラン（2ランは同一シード、1ランは別シード）を実施し、以下を計測する:
札の手札滞留時間と最後まで出さなかった札／同一シード間で配置が変わったか／予告を見て配置を
変えたか／勝敗理由の記述／主観判定／一時停止の回数と累計時間。全項目を判定に使う。

## 層構成

```
src/features/ashen-rampart/
├── domain/
│   ├── board/        # 盤面（経路・設置スロット・地形）
│   ├── cards/         # カード定義・プリセットデッキ・手札/デッキ/墓地の規則
│   ├── combat/         # CombatState・stepTick（決定的・純粋関数）・敵・ウェーブ
│   └── run/            # 未使用領域込みの将来拡張用（現状は combat に集約）
├── application/
│   ├── ports/          # RandomPort・PlayLogPort
│   └── use-cases/      # start-run 等
├── infrastructure/      # シード付き乱数・localStorage 行動ログ
└── presentation/        # ゲームループ（useAshenRampartGame）・盤面・手札・状態表示・凡例

src/pages/AshenRampartPage.tsx   # ページコンポーネント（薄いラッパー）
```

- **戦闘は決定的純粋関数**: `stepTick(state, actions, map) → state` を乱数なしで1 tick 進める。
  時間を進めるのは `presentation` の `setInterval` だけで、ロジックは一切持たせない
- **StrictMode 対応**: ループの `setState` updater は副作用を持たない純粋関数として実装する
  （updater 内でのみ ref を読む/書くと StrictMode の二重呼び出しで操作が握り潰される）

## テスト

- Jest。テストは対象と同じディレクトリに `*.test.ts(x)` で配置
- `domain/combat/balance.test.ts` は支配戦略が生まれていないかの回帰テスト。バランス調整の
  たびに自動で再検証される
