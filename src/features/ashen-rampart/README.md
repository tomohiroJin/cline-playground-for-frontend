## コンセプト（反証可能な面白さの仮説）

> プレイヤーは有限の札を「今切るか、この先のために温存するか」で配分し、
> 切り時の判断が当たった／外れたことを実感して面白がる。反復3 では、これに
> 「2レーンのどちらへ前線を厚くするか」という配分の判断が加わる。

MTG × RTS × TD というジャンルの組み合わせは仮説ではなく手段。判定対象は上記の一文に限る。
この仮説が成立するための必要条件（機構で保証する）:

- 札を**全部は出せない**（デッキ20枚に対し、ラン中に配置できる回数には上限がある）
- 出す／出さないの選択が**排他的**（魔力炉だけは配置クールダウン中に他の魔力炉を出せない。
  他の札はマナが唯一の律速で、置きたい瞬間に置ける）
- 出さなかったことに**代償がある**（手札上限に達すればドローが墓地へ直行する）

## 遊び方

1. リアルタイムで敵ウェーブが進行する（`stepTick` が 100ms ごとに1 tick 進める）
2. 手札から守り手（塔）・罠・呪文・魔力炉を選び、盤面のセルに配置する（マナを消費）。
   設置マスという概念は無く、砦セル以外ならどこにでも置ける。守り手を経路上に置けば
   敵をその場でブロックできる（食い止めた分だけ守り手のHPが削れる）
3. 燠火（業火の設置跡）は再点火でき、終盤に手札もマナも尽きても操作対象として残る
4. 砦のライフ（初期12）が0になる前に、4ウェーブ・2レーン（北=短い直線／南=長い迂回）の
   敵をすべて処理しきれば勝利
5. スペースキーまたは⏸ボタンで一時停止できる（戦術的優位は与えない。認知負荷の緩和が目的）
6. 決着後、シードとプリセット（速攻型／重厚型）を指定して同一条件・別条件で再挑戦できる

## 主要な機構

- **カード14種**（コスト帯0〜5）: 魔力炉（マナ源・経路上には置けない）・石壁（HP60・攻撃0の
  純ブロッカー）・弓兵／弩砲／火砲台／投石機／徹甲弩（貫通）の攻撃塔5種・篝火／鍛冶場
  （攻撃せず隣接する守り手を強化）・棘罠／落網（飛行を地上化）の罠2種・業火（燠火として
  残り再点火可能）・時泥（減速呪文）・徴発（山札を見て1枚選ぶ）
- **HPと攻撃力の逆相関**: 石壁60/0 → 火砲台16/12 → 徹甲弩14/14 → 弩砲12/9 → 投石機10/18 →
  弓兵8/4。前に出すほど硬く、後ろに置くほど火力に振れる。同名カード上限3枚（魔力炉のみ
  無制限）と合わせ、単一カードへの偏りが構築規則上できない
- **敵5種とカウンター要求**: 雑兵（基礎）・俊足（テンポ）・重装（単体高火力）・鴉（飛行。
  対空手段が無いと必ず負ける）・群れ（範囲攻撃または貫通のどちらかを要求。範囲攻撃だけを
  持たなくても貫通が代替するため単独では拘束にならない）。「最高効率のカードには必ず
  効かない相手を作る」原則で支配戦略の成立を防いでいる
  （`domain/combat/balance.test.ts` で回帰検証）
- **地形**: 高台（火力+30%）・滞留セル（敵の移動速度を落とす）
- **プリセットデッキ2種**（速攻型・重厚型）。デッキ構築 UI の代替であり、判定するのは
  「デッキ構築の面白さ」ではなく「ラン中の札の配分」

## 判定の観点（設計書 §9.1）

同一プリセットデッキで3ラン実施し、以下7項目を計測する（7項目目「前回より面白くなったか」
は数値化できないため画面には出ない）: 2レーンへの配置数の配分／ブロッカーを置いたレーン内
位置／失った守り手の数と種類／経路上・経路外の配置比率／鴉の撃破位置の平均進捗／使わなかった
カード種と使ったコスト帯の分布／前回より面白くなったか。

## 層構成

```
src/features/ashen-rampart/
├── domain/
│   ├── board/          # 盤面（2レーンの経路・地形）。設置マスという概念は持たない
│   ├── cards/           # カード定義・プリセットデッキ・手札/デッキ/墓地の規則
│   └── combat/           # CombatState・stepTick（決定的・純粋関数）・敵・ウェーブ
├── application/
│   ├── ports/            # RandomPort・PlayLogPort
│   └── use-cases/        # start-run 等
├── infrastructure/        # シード付き乱数・localStorage 行動ログ
└── presentation/          # ゲームループ（useAshenRampartGame）・盤面・手札・状態表示・凡例

src/pages/AshenRampartPage.tsx   # ページコンポーネント（薄いラッパー）
```

- **戦闘は決定的純粋関数**: `stepTick(state, actions, map) → state` を乱数なしで1 tick 進める。
  時間を進めるのは `presentation` の `setInterval` だけで、ロジックは一切持たせない
- **StrictMode 対応**: ループの `setState` updater は副作用を持たない純粋関数として実装する
  （updater 内でのみ ref を読む/書くと StrictMode の二重呼び出しで操作が握り潰される）
