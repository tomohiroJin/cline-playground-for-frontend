## 1. 判定

反復3の問いは「**前線をどこに敷き、何を捨てるか**」だった。**その問いに対する不満が1件も出ていない。**

### 1.1 何が言われなかったか

反復2の判定でも用いた読み方（前回の不満が今回挙がらなければ達成の証拠）を継続する。今回のフィードバック6件に、次は**1件も含まれていない**。

| 前回までの不満 | 今回 |
|---|---|
| 前線をどこに敷けばいいか分からない（本反復の問い） | 挙がらず |
| 飛行が途中から突然現れるのはずる過ぎる | 挙がらず |
| 対空を大量に入れることになる | 挙がらず |
| マナがあるのに置けない | 挙がらず |
| **似たようなものがコスト違いになっている** | **挙がらず** |

### 1.2 同じ人が正反対のことを言った

最も強い証拠がこれである。

| 反復2 | 反復3 |
|---|---|
| 種類が少ないのは**いい**が、似たものが多くて分かりにくい | **カードの種類がもっと欲しい** |

反復3は枚数を14種のまま据え置き、コスト帯を 0〜5 に広げてHPと攻撃力を逆相関させただけである。**枚数を1枚も増やさずに「もっと欲しい」へ反転した。** 軸を分けた変更が効いて、増やす余地が生まれたということである。

**同一人物の正反対の発言は、間に入れた変更が効いたことを示す証拠になりうる。** 単に「良くなった」と言われるより情報量が多い。

## 2. フィードバックと分類

| # | フィードバック | 性質 |
|---|---|---|
| 1 | **設置後の内容がわかりにくいのでもっとグラフィカルにしてほしい** | 表現 |
| 2 | 最初の面としてはいいが、どんどん難しくなってほしい | 次段階（マップ） |
| 3 | ストーリーとかあるとゲームとして楽しそう | 次段階（物語） |
| 4 | カードの種類がもっと欲しい | 語彙の拡張 |
| 5 | 敵に向かっていくようなカードもあるといいかも | 語彙の拡張（新機構） |
| 6 | カードに一定の種類をつけてもいい（MTG のクリーチャー・アーティファクト・エンチャント・インスタントのような） | 表現 |

### 2.1 #1 と #6 は「既にあるものが見えていない」

**カードの種別はドメインに既に存在する。** `CardType = 'tower' | 'trap' | 'spell' | 'reactor' | 'ember' | 'levy'` として型で定義され、配置先の決定（`placementKindOf`）にも使われている。**プレイヤーには一切見せていない。**

このコンセプトは MTG を出発点にしており、マナのカード化・デッキ構築・同名上限を借りた。**カードタイプという MTG の語彙も内部には借りていたが、画面に出していなかった。**

#1 も同種である。守り手にはHP・攻撃力・射程・攻撃間隔・対空可否・範囲・貫通という7つの属性があるが、盤面に出ているのはHPバーとカード名だけである。

### 2.2 #1 は3回持ち越した項目である

「デザインの全面見直し」は**反復1から3回連続で deferred**してきた。

| 反復 | 扱い |
|---|---|
| 1 | ホームボタンと文字の重なりだけ個別修正、全面見直しは別途 |
| 2 | 「本反復の問いと独立している」として YAGNI に記載 |
| 3 | 同上 |

そして今回、**6件のうち最初に挙がった**。他の不満が解消されるにつれて相対的に前へ出てきた。

**「後回しにしてよい」は「ずっと後回しにしてよい」ではない。** 持ち越しの回数を記録していなければ、これは4回目の持ち越しになっていた。

## 3. 次の反復で扱うもの

> **置いたもの・手札が何であるか、見て分かるか。**

#1 と #6 を中心に、盤面とカードの表現を扱う。

**#4・#5（カードを増やす・進軍する守り手）を先にやらない理由**は、表現が粗いまま種類を増やすと、増やした端から「わかりにくい」に戻るためである。反復2で「攻撃が見えない」を直したからこそ反復3の「配分の判断」が意味を持ったのと同じ構造で、**表現は先行投資として効く**。

**#2・#3（難度カーブ・物語）は出口条件が解禁した次段階**であり、表現を固めた後に着手する。

## 4. この反復から得た教訓

**同じ人の正反対の発言は、間に入れた変更が効いた証拠になる。** 「種類が少ないのはいい」→「もっと種類が欲しい」は、枚数を1枚も変えずに起きた反転である（§1.2）。良し悪しの評価より、**評価の向きが変わったこと**のほうが情報量が多い。

**一度診断した欠陥の形は、別の場所に現れる。** 反復2で直したのは「`TickEvent` が計算済みなのに描画されていない」だった。今回出た #6 は「`CardType` が定義済みなのに表示されていない」であり、**同じ形の欠落がカードの語彙に存在していた**。欠陥を直すときは、その欠陥の「形」で他の領域も点検すべきだった。

**後回しの回数を数える。** #1 は3回持ち越して今回最上位に来た（§2.2）。個々の反復では毎回「本反復の問いと独立している」という正しい判断だったが、**それが3回続いたことは記録しなければ見えない**。
