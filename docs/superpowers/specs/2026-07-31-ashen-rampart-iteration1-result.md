## 1. 判定

> **ゲームとしては要約面白みが出てきました。ですが全体的に弱いしまだまだだということも同時に分かりました。**（ユーザー実プレイ評）

**継続**。反復1 の3つの狙いのうち「配分の問題が毎回同じ形にならないか」には手応えが出た一方、**その手応えを支える土台（盤面の可読性・操作の応答）が弱い**ことが同時に判明した。

設計書 §7 の出口条件は「6項目すべてを記録したうえで Yes なら次段階（マップ追加・ボス・物語）へ」だったが、**次段階へは進まない**。挙がった問題は新しいコンテンツを足しても解決しない種類のものであり、先に土台を直す。

### 2.1 7件のうち3件は同じ原因である

**#2・#5・#7 はすべて「盤面で起きていることが、計算はされているのに見えない」に帰着する。**

`TickEvent` は `shot`（どの塔がどの敵を撃ったか）・`trap`・`defeat`・`leak`・`rejected`（なぜ操作が通らなかったか）をすべて持っている。domain は正しく計算している。UI がそれを読んでいない。

**これは #183 の調査で特定した欠陥の再発である。** 前コンセプトでも `TickEvent` は `simulate-wave.ts` に存在し UI 未使用だった。当時この欠落を「環④＝観戦が空白」と診断し、S2 として計画していた。PoC で `stepTick` へ全面的に書き直した際、**イベントの計算は移植したが描画は最後まで作られなかった**。

一度診断した欠陥が、実装を書き直したときに同じ形で戻ってきた。

### 2.2 マナ事故は「MTG に倣った」ことの取りこぼしである

このコンセプトは MTG を出発点にしている。マナをカード化し、土地に相当する魔力炉を作った。**しかし同名上限3枚という制約を、マナ源にも適用してしまった。**

MTG の基本土地に枚数制限が無いのは偶然ではない。マナ基盤は「事故らないだけの枚数を積めること」が前提で、その上で色や曲線の選択が意味を持つ。**上限を課すと「積むか積まないか」の選択そのものが消え、事故が構造として残る。**

デッキ20枚に対する魔力炉3枚＝15% は、MTG の 42.5% の 1/3 である。これは「配分が難しい」のではなく「配分が不可能」に近い。

### 2.3 死にマス63%は「空間パズル」の前提を壊している

PR #171 で「盤面の空間パズル」を主軸に据え、射程を希少化し、高台と滞留を非一致に置いて二律背反を作った。その設計は温存されている。

しかし実際に置けるのは 63マス中23マスで、うち高台は2マス・滞留は3マスである。**選択肢の母数が小さすぎて、空間の判断が成立していない。**

## 3. 次の反復で扱うもの

問題は3つの層に分かれる。**下の層から直す**（[[game-fun-verification-methodology]] のビルド順）。

### 層1: 盤面が見えない（#2・#5・#7）— 最優先

`TickEvent` を描画する。射撃線・被弾・撃破・漏れ・**拒否理由**。これは新しいドメインを必要としない——データはすでにある。

**#183 の調査結論をそのまま適用できる。** 「配置して観戦する」型で観戦を退屈にしない工夫として抽出した6パターンのうち、①TickEvent 描画 は「実装コスト低・効果大」と評価していた。

### 層2: 操作が通らない（#2・#5・#6）

- 配置クールダウンを**盤面に何かを置くカードだけ**に課す（徴発・時泥のような即時札を除外する）
- 拒否理由を UI に出す
- 手札が溢れるとき、**捨てる札をプレイヤーに選ばせる**

### 層3: 構造的な窮屈さ（#3・#4）

- **魔力炉の同名上限を外す**（またはマナ源だけ別枠にする）。バランス較正のやり直しが必要
- 設置可能マスを増やす。63% の死にマスを減らす

### 層外: デザイン（#1）

ホームボタンと文字の重なりは個別の不具合だが、ユーザーは「デザインは後でしっかり見直す必要がありそう」と述べている。**個別修正に留め、全面的な見直しは別途**とする。

## 4. この反復から得た教訓

**一度診断した欠陥は、実装を書き直すと戻ってくる。** #183 で「TickEvent が計算済みなのに描画されていない」を特定し、S2 として計画していた。PoC の全面書き直しで計算部分は移植されたが、描画は作られないまま反復1 まで来た。**診断の記録は、次の実装計画のチェックリストとして使わなければ効かない。**

**元ネタから機構を借りるとき、その機構が成立している条件も一緒に借りる必要がある。** MTG のマナ基盤は「土地に枚数制限が無い」ことで成立している。マナのカード化だけを借りて上限は自作のルール（同名3枚）に従わせた結果、事故が構造として残った。

**「支配戦略が無いこと」を守っても、遊べることは保証されない。** 反復1 では balance.test.ts の不変条件に多くを費やし、支配戦略の再発は防いだ。しかし「置ける場所が23マスしかない」「拒否理由が見えない」「攻撃が見えない」は自動検算では検出できない。**シミュレーションが測れるのは勝敗であって、体験ではない。**
