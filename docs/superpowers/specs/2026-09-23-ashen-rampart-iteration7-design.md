### 2.1 反復6 の項目2b（獲得が判断だったか）を客観指標から外す

反復6 の 2b は「次ステージの要求軸を満たす札を選んだ割合」だった。**軸を捨てると測る対象が無い。**
代わりに「飛行が出る → 対空札」のような写像を作れば、**捨てた軸を裏口から戻すことになる。**
したがって 2b は §2.3 の「測れない」側に置き、項目8 の主観で扱う。

### 2.2 主観の文面（項目8・9）

反復6 §7.4 の文面とコード化を引き継ぎ、次の2問を足す。**誘導を避けるため、敵の名前や機構を文面に入れない。**

- 「獲得の3枚から選ぶとき、何を考えて選びましたか」
  - 肯定: 次のステージの予告・敵・マップに言及する
  - 否定: 札の強さのみ／何も考えていない
- 「遠征の中で、それまでと手を変えた場面はありましたか」
  - 肯定: 具体的なステージや敵を挙げる
  - 否定: 無い／思い出せない

**項目9(a) は、上の回答の中で盾衛・癒し手の能力（装甲・回復）に判定者から触れたかで判定する。**
能力について直接問う質問は、上の2問の後に置く（先に置くと (a) が汚染される）。

### 2.3 測れないことの宣言

| 対象 | 較正ハーネスで測れるか |
|---|---|
| 層ごとの難度の単調性・層3 到達率 | 測れる |

| 適応ゼロのときの配置変化量（項目3 の基準） | 測れる（反実仮想） |

| 摩耗・優先撃破・配分・持久 | 測れない（反復6 §7.1 と同じ） |

### 2.4 反証条件

**項目3 または項目4 が事前予測を外したら、主観がどうであれ問いの判定を Yes にしない**
（客観の失敗を主観で救わせない。反復6 §7.5 の構造）。

## 3. 段階1 — 遠征 UI（暫定ステージのまま画面から遊べるようにする）

### 3.1 現状

画面は `building → briefing → running`（単発の戦闘）。遠征のドメイン
（`ExpeditionState` の `stage / offer / ended`）とユースケース
（`startExpedition` / `startStage` / `advanceStage`）は揃っているが、**画面から呼ばれていない。**

### 3.2 画面の流れ — 単発の戦闘モードを遠征で置き換える

```
構築 → ブリーフィング → [ステージ → 獲得3択] ×2 → ステージ3 → 遠征の決着
                          ↑ 敗北したらその場で決着へ
```

**単発の戦闘は画面から消える**（ユーザー承認済み）。

| 部品 | 役割 |
|---|---|
| `StageView`（`RunView` を改名・縮小） | **1ステージの戦闘。** マップと初期状態（持ち越しライフ込み）を受け取る。決着時は勝敗と「獲得へ進む／遠征の結果へ」だけを出す。勝敗理由の記録・集計・再挑戦は `ExpeditionSummary` へ移す |
| `useExpedition`（新設） | 遠征の状態の組み立て。**ユースケース経由で呼ぶ**（CLAUDE.md の層の規則） |

### 4.1 新敵（数値はすべて較正対象）

反復6 §5.4 を引き継ぎ、「要求するもの」の列を削除する。

|---|---|---|---|
| `warden` | 盾衛 | **装甲**: 1ヒットごとに一定値を引く（最低0） | hp 45・armor 4・speed 0.06・attack 8・attackRange 1.5 |

`EnemySpec` に `armor?: number` と `heal?: { amount; intervalTicks; radius }` を足す。

### 4.2 ドメインの実装順（反復6 §5.4.1・§5.4.2・§8.4 の制約をそのまま守る）

   （`step-tick.ts` の罠・射撃・範囲・貫通・業火）を共通関数へ置き換える。
   装甲は**1ヒットごと**に引き、**`dealt > 0` のときだけ `sourceById` を書き換える**
   （`combat-state.ts` の契約「最後に**削った**者に帰属する」を守る）
2. **敵の回復は罠より前**（`hpById` を種まきした直後）に置く。tick 内の蘇生経路が構造的に消える
3. **`attackersFor` を「ブロックしている敵を優先」に直す**（持ち越し2回目）。
   反復5 §12.1.1 の「直さない理由」は「較正の前提を全部測り直すことになる」だったが、

### 5.1 難度の土台（3つの静的な量）

**いずれもウェーブ台本とマップだけから計算できる。宣言ではないので、宣言と実態がずれる余地が無い。**

| 量 | 定義 | 層1 → 層3 |
|---|---|---|
